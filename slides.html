Prompt-Driven Annotation Pipeline for Classical Text Commentary

Chen Zhan · 2026.03

Why This Project?

  • Classical texts (Latin, German baroque, Classical Chinese) need multi-layered commentary
  • Traditional commentary is expensive: one expert, one text, months of work
  • LLMs are good at individual annotation tasks, but lack structured workflow

Goal: a modular pipeline where each stage is a well-defined prompt,
allowing multiple LLMs (or humans) to collaborate on annotation.

What It Produces

Static web pages with dual-column layout + interactive commentary:

Western Classics

  • Ovid Metamorphoses I (Latin-Chinese)
  • Brentano Sprich aus der Ferne (German-Chinese)
  • Gryphius Papinianus I,1 (German-Chinese)

Chinese Classics

  • Zuozhuan Left Commentary (Classical Chinese-English)
  • Yantie Lun Discourses on Salt & Iron
  • Jinkui Yaolue Essential Prescriptions Ch.16

Pure frontend (GitHub Pages), no build tools, no backend.

The Pipeline: 6 Stages

1. Segmentation
Raw Text → Sections → 2. Word Selection
Which words to annotate? → 3. Word Annotation

4. Commentary
Multi-tab analysis → 5. Translation
Scholarly translation → 6. Assembly

Each stage is a pure function: defined input → defined output.
Every stage can be done by a different model, a human, or both.

Stage 1-2: Segmentation & Word Selection

1. Segmentation

Split raw text into sections with titles.

Raw text → Section[]
{ id: 1,
  title: "The Official's Warning",
  lines: [{zh: "大夫曰..."}] }

2. Word Selection

Pick 4-8 words per section that need annotation.
The most judgment-heavy stage.

{ form: "賢良",
  reason: "Technical term for
    the Confucian scholars",
  priority: "high" }

Key design: selection is separated from annotation — different skills, different models.

Stage 3: Word Annotation

For each selected word, generate a structured annotation entry:

{
  "form": "箕子",
  "pinyin": "Jīzǐ",
  "pos": "proper",    // noun | verb | adj | adv | prep | part | proper | medical
  "cls": "w-proper",  // CSS class for color-coding
  "info": "Jizi — uncle of the last Shang king. When the king began
           using ivory chopsticks, Jizi foresaw that this small
           luxury would escalate...",
  "gloss": "Jizi (Shang prince who warned against luxury)"
}

Each annotation is self-contained → can be generated in parallel, cross-validated by different models.

Stage 4: Commentary Generation

Multi-tab analysis, configured by genre:

GenreTabs
German PoetryGrammar, Meaning, Interpretation, Translation Note, Alt-Translation, Meter
Chinese HistoryGrammar, Context, Commentary, Narrative, Spring&Autumn
Chinese TCMGrammar, Medicine, Commentary, Formula, Clinical
Chinese PoliticalGrammar, Context, Rhetoric, Notes, Translation

Each tab is a prompt template in framework/prompts/ — HTML output, not Markdown.

The Core: Prompt Engineering

  • Schema as contract — strict JSON schema for each stage's I/O; the LLM only needs to fill the template
  • Audience parameter — the same text gets different annotations for different readers (Sinology student vs. TCM practitioner)
  • Genre parameter — controls which commentary tabs are generated
  • Separation of concerns — word selection (literary judgment) vs. word annotation (lexicographic precision) are different skills
  • Validation — node framework/validate.js catches schema violations before they reach the webpage

Multi-Model Collaboration

A. Sequential Pipeline

Model A → Model B → Model C → Model D
(each stage by a specialist)

B. Parallel Annotation

           ┌─ Model A (words 1-3)
Word List ─┤─ Model B (words 4-6)
           └─ Model C (words 7-8)

C. Cross-Validation

Text ─> Model A ──┐
                   ├─> Human merge
Text ─> Model B ──┘

D. Specialist Routing

       ┌─ Model A (grammar, rhetoric)
Text ──┤
       └─ Model B (history, context)

Because each stage has a defined schema, models are interchangeable.

Interactive Annotator Tool

  • A web-based UI for running the pipeline step-by-step
  • Paste raw text → walk through each stage → export JS data file
  • Human can override at any stage (edit word selections, fix annotations)
  • Preview the final commentary page in real-time

annotator.html — live on GitHub Pages

Tech Stack

  • Frontend: Vanilla HTML/CSS/JS, no build tools
  • Data: JS constants in data/*.js, imported via <script>
  • Validation: Node.js schema checker (framework/schema.js)
  • Deployment: GitHub Pages, automatic on push to main
  • Prompts: Markdown templates in framework/prompts/

Deliberately minimal — the complexity is in the prompts, not the code.

Commentary in Action

Five examples from the live site showing
how structured commentary aids language learning

Ex 1. Historical False Friend Gryphius

"Der reichen Ehre schaut wie schlecht der Pöfel geh"

Without commentary:

A modern German reader reads schlecht as "bad" — wrong.

With commentary:

17th-century schlecht = "simple, lowly, humble".
Also: Pöfel = Pöbel (commoners), geh = archaic conjugation.

Lesson: historical texts need historical lexicography, not just a dictionary.

Ex 2. Disambiguating Medical Terms Jinkui Yaolue

脈動而弱，動即為驚，弱則為悸
驚 jīng (fright)悸 jì (palpitation)
CauseExternal stimulus → shock scatters qiInternal deficiency → qi/blood depleted
PulseStirring (動) → excessWeak (弱) → deficiency
PatternExcess (實)Deficiency (虛)

Lesson: two similar-looking terms describe opposite diagnostic conditions. Commentary prevents clinical confusion.

Ex 3. Essential Historical Context Zuozhuan

欲立之，亟請於武公，公弗許

Surface reading:

"A mother wants to change the heir. A family dispute."

With context tab:

Zhou succession follows 立嫡以長 (primogeniture). Lady Jiang's request is a constitutional violation threatening the entire feudal order.

Lesson: without institutional context, political texts collapse into personal anecdotes.

Ex 4. Prosody Made Visible Gryphius

Wer ü·ber al·le steigt / und von der stol·tzen Höh

The meter tab provides:

  • Alexandriner: 6-foot iambic with medial caesura after foot 3
  • Syllable-by-syllable scansion: u — u — u — / u — u — u —(u)
  • Rhyme scheme: aa bb cc dd (paired couplets)
  • Feminine ending (+1 syllable) vs. masculine ending explained

Lesson: scansion annotation lets students hear the meter, not just be told about it.

Ex 5. Rhetorical Structure & Irony Yantie Lun

Three-act structure revealed by commentary:

SectionTextRhetoric tab reveals
1Grandee compares scholars to cicadas that "fall silent when autumn comes"Metaphor as political threat
2Worthy Man invokes Confucius, Bi Gan, Wu ZixuRefuses insult; elevates to moral principle
3大夫默然。The Grandee is silenced — by his own metaphor

Lesson: 4 characters carry devastating irony — but only if you see the structural relationship across sections.

Takeaway

Classical text commentary = a structured prompt engineering problem.

  • Break the task into stages with clear I/O schemas
  • Let each stage be a self-contained prompt
  • LLMs become reliable, composable annotators
